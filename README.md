# NimbusTrace – Self-Healing Infrastructure

## Project Overview

**NimbusTrace** is a DevOps-based self-healing infrastructure project designed to monitor application health, detect service failures, and automatically recover the application using Docker, Prometheus, Alertmanager, and Ansible.

The project demonstrates automated monitoring, alerting, and recovery to improve application availability and reduce manual intervention.

## Objectives

- Monitor application health continuously.
- Detect application failures automatically.
- Trigger alerts when the application becomes unhealthy.
- Automatically recover failed application containers.
- Maintain recovery logs for troubleshooting.
- Improve application availability and reliability.

## Project Architecture

1. The Node.js application runs inside a Docker container.
2. Prometheus monitors the application and collects metrics.
3. Prometheus detects application health issues.
4. Alertmanager manages alerts generated by Prometheus.
5. Ansible executes the recovery process.
6. The recovery script restarts the failed application container.
7. Recovery logs record the automated actions.

## Features

### Application Monitoring
Prometheus continuously monitors the application and collects health and performance metrics.

### Alert Management
Alertmanager manages alerts generated when the application encounters failures.

### Automated Recovery
Ansible automates the recovery process by restarting the failed application container.

### Containerization
Docker packages the Node.js application into a container for consistent deployment.

### Recovery Logging
Recovery activities are recorded in log files for troubleshooting and verification.

### Web Dashboard
The monitoring dashboard provides visibility into application health and infrastructure status.

## Installation and Setup

### 1. Clone the Repository

```bash
git clone https://github.com/madasuswathi/self-healing-infrastructure-project.git
```

### 2. Navigate to the Project Directory

```bash
cd self-healing-infrastructure-project
```

### 3. Start the Application and Monitoring Stack


### 4. Verify Running Containers

## Self-Healing Test

The self-healing functionality can be tested by intentionally stopping the monitored application container.

### Step 1: Stop the Application Container

```bash
docker stop nimbustrace-monitored-app
```

### Step 2: Verify the Container Status

```bash
docker inspect -f '{{.State.Running}}' nimbustrace-monitored-app
```

### Step 3: Observe the Recovery Process

Check the recovery log:

```bash
tail -n 20 logs/self-healing.log
```

### Step 4: Verify Automatic Recovery

```bash
docker ps
```

The monitored application container should return to the running state after the recovery process executes.
